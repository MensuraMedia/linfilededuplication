Building a File Deduplication Application for Debian Linux using a GTK4 + Libadwaita Dashboard Framework
Important Note on the Specified Framework

The repository https://github.com/MensuraMedia/gtk4-dashboard-template 
This instruction set therefore uses the closest modern, production-ready equivalent pattern that matches the intended style: a GTK4 + Libadwaita dashboard-style application (sidebar navigation, modular pages/widgets, Adwaita styling, Python or C backend where necessary - but should favor python). It draws structural inspiration from well-maintained public GTK4/Adwaita dashboard and application templates (e.g., Python-based dashboard patterns, Meson + Blueprint/UI templates, and GNOME HIG-compliant layouts).
All code, architecture, and packaging instructions are tailored for Debian 12/13 (Bookworm/Trixie) and derivatives.

Note: This system is being developed on a linux debian mint environment.

1. Project Goals & Scope
Create a native Linux desktop application named DedupeDash (or user-chosen name) that:

Implements the top-20 file deduplication comparison features previously defined (cryptographic hashing, size pre-filter, progressive hashing, fixed/variable chunking, perceptual hashing for images, fuzzy hashing, metadata comparison, deep embeddings where feasible, policy engine, hard-link support, etc.).
Provides a modern, responsive dashboard-style UI with:
Left sidebar navigation (Scan, Results, Settings, History, About).
Main content area that switches between modular “pages”.
Progress indicators, results lists with previews (especially images), selection controls, and safe deletion/hard-link actions.

Runs natively on Debian with GTK 4 + Libadwaita.
Supports both exact and near-duplicate detection across all file types, with special emphasis on images.
Is packaged as a .deb and optionally Flatpak.
Follows GNOME HIG and is keyboard-accessible.


2. Technology Stack (Debian-native)
Recommended primary stack (easiest for rapid development + dashboard style):

Language: Python 3.11+
UI: GTK 4 + Libadwaita (gi.repository)
Build: Meson + Ninja (or pure Python with pyproject.toml + setuptools for simpler cases)
Hashing / Dedup engine: hashlib, xxhash, imagehash (perceptual), ssdeep / tlsh (fuzzy), Pillow, optionally onnxruntime or torch for embeddings
Async / background work: GLib, Gio, or asyncio + threading
Packaging: python3-gi, libadwaita-1, Debian packaging tools

Alternative high-performance stacks (if needed):

C + GTK4 + Libadwaita + Meson + Blueprint
Rust + gtk4-rs + libadwaita-rs

Debian packages to install for development:

sudo apt update
sudo apt install -y \
  python3-gi python3-gi-cairo gir1.2-gtk-4.0 gir1.2-adw-1 \
  libadwaita-1-dev libgtk-4-dev \
  python3-pil python3-xxhash python3-imagehash \
  meson ninja-build pkg-config \
  blueprint-compiler  # if using .blp files

4. Core Deduplication Engine Requirements (Must Implement)
Map the previous top-20 features into concrete modules:

Exact match pipeline (mandatory first stage)
Size pre-filter
Progressive hash (first 4–64 KB then full)
Cryptographic full-file hash (SHA-256 preferred, xxHash for speed)
Optional byte-for-byte verification

Near-duplicate / content-aware
Fixed-size and Content-Defined Chunking (CDC)
Fuzzy hashing (ssdeep / TLSH)
Perceptual hashing for images (aHash, dHash, pHash, wHash) with configurable Hamming distance
Optional deep embedding similarity (CLIP-style or lightweight CNN) for semantic duplicates

Metadata & policy layer
EXIF / ID3 / document properties comparison
Filename fuzzy matching
Keep/delete policy engine (prefer newer, prefer higher quality, prefer specific folders, hard-link instead of delete, etc.)

Safety & UX features
Dry-run mode
Preview of duplicate groups (thumbnails for images)
Hard-link / symlink / move-to-trash options
Progress reporting via GLib signals or callbacks
Cancellation support


Implement the engine as a pure Python (or C) library that can run headless and report results via callbacks or a result model that the UI consumes.

5. UI Architecture (Dashboard Pattern)

Use Adw.Application + Adw.ApplicationWindow
Left sidebar: Adw.NavigationSplitView or Gtk.ListBox + Adw.ViewStack / Adw.Leaflet
Each “page” is a self-contained widget that can be swapped in the content area
Results page: Gtk.ColumnView or Gtk.ListView with custom factories showing:
Group header (hash / similarity score)
File list with path, size, modified date, thumbnail
Checkboxes for selection + “Keep one / Delete others / Hard-link” actions

Scan page: folder chooser, options toggles (exact only / near-duplicates / images only / include hidden / min size), start/stop button, live progress bar + log
Settings page: hash algorithms, perceptual thresholds, default policy, exclusion patterns
Use Adw.Toast for non-blocking feedback
Support dark/light mode automatically via Adwaita


6. Implementation Steps for an AI / Developer

Scaffold the project from a clean GTK4 + Libadwaita template (Python preferred for speed).
Create the Application and Window classes following GNOME patterns.
Build the navigation shell first (sidebar + empty pages).
Implement the core scanner as an independent module with unit tests.
Wire the scanner to the UI via GObject signals or a result model (Gio.ListStore of duplicate groups).
Add progressive result population so the UI stays responsive.
Implement safe deletion / hard-linking with confirmation dialogs (Adw.AlertDialog).
Add thumbnail generation (Pillow + Gdk.Texture) for image groups.
Package:
Desktop file + metainfo
Debian package (dpkg-buildpackage or dh)
Optional Flatpak manifest



7. Debian Packaging & Distribution

Create a proper debian/ directory or use python3-setuptools + stdeb.
Dependencies in control file: python3-gi, gir1.2-gtk-4.0, gir1.2-adw-1, python3-pil, ...
Install icons, desktop file, and metainfo under standard FHS paths.

8. Quality & Safety Requirements

Never delete without explicit user confirmation (or a clear “auto” mode that is off by default).
Always offer a dry-run / preview.
Log all actions.
Handle permission errors gracefully.
Support cancellation of long-running scans.
Follow GNOME accessibility guidelines (keyboard navigation, screen-reader labels).

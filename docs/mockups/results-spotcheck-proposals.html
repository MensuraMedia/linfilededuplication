“How duplicates are decided” card

A persistent explainer at the top of Results so the keep/delete logic is transparent.

How LinFileDedup decides what to keep

One file in every group is always kept — only the extra copies are ever removed.

  1. Same size & type. The newest copy is kept; the older copies are marked for deletion.
  2. Same type, different size. The largest (highest-quality) is kept; the smaller copies are marked for deletion. — higher-resolution images win.
  3. Backups detected. The newest backup is kept; older backups are marked for deletion.
  4. Name tells. An original beats a “copy”, “(1)”, “resized” derivative of the same content.
  5. Already hard-linked. Files that share one physical copy are left alone — there’s nothing to reclaim.

Option to delete every copy

A per-group control to remove all copies when you don’t want to keep any — with a clear guard, since no copy would remain.

EXACT · SHA-256 2 files · 8.0 MB Keep: Newest ▾ Delete all copies ▾
▤IMG_2381.jpg4.0 MB~/Pictures Delete ✓
▤IMG_2381 (1).jpg4.0 MB~/Downloads Delete ✓
⚠ No copy will remain in this group. These files move to Trash (recoverable) — Hard-link is disabled when nothing is kept.

Default stays “keep one”. Choosing Delete all copies flips every row to the red marker and shows the guard above; a confirm dialog still appears before anything moves.
